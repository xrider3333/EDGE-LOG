# %-ON-ADJUSTED sweep (DISC verifier item 2, 2026-10-09): which files read percent levels, and what an additive back-adjusted master does to them

**Answer to MANAGER's open ask (1), from the engine roll guard: REFUSE.** A file that reads percent or ratio levels
should be refused on an ADDITIVELY back-adjusted master (`db_adj_*`, `db_fadj_*`).
- **It costs nothing today.** No saved run and no BOOK #463 leg runs a percent file on such a master.
- **The error is large and not only early-years.** On the adjusted master, NOISE #422 reads ROC 37.8 instead of 52.2.
- **Ratio files are fine elsewhere:**
  - on the raw master, for an intraday file;
  - on a multiplicatively adjusted series (split-adjusted stock bars, or the guard's ratio series).

## Method
Each file's champion was run three times on the same window:
1. as it is;
2. with every OHLC price + C (C = 3,000 NQ points / 1,000 ES points);
3. with every price x 2 (and the cost x 2; points divided back by 2).

How the result is classed:
- **difference** = no trade moves under +C. These files are safe on an additive master.
- **ratio** = trades move under +C but not under x k. These files read percent levels.
- **raw** = trades move under both.

The control is RSIDIV #163, whose 12.5% trailing stop is percent-based. It classes as **ratio**: +C moves 33% of its
trades and changes P&L by +43%.

Script: `C:\EdgeLog\_anatomy_cache\pct_adj\shift_scale_test.py`, output in `sst_<run>.json`.

- **The distortion is not only an early-years problem.** The additive offset at any date is the sum of all later roll
  offsets, so it is still about +2,000 NQ points (about 10%) in 2024.
  - #382, 2024: $89,840 on the true master vs $105,107 adjusted.
  - #382, 2020: $58,844 vs $46,802.
- **So:** an adjusted-master percent run can read too high or too low in any year, and the yearly errors do not cancel.
